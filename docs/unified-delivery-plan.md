# 飞书与 QQ 统一转发实施计划

## 目标与总体验收

一个控制面管理两路采集及统一投递调度器。顶部支持启动全部、停止全部，并显示飞书与 QQ 各自状态；Tab 保留来源与目标配置，并支持单独启停。

飞书继续通过 API 获取文本、图片及现有富文本内容；QQ 第一版读取系统通知文本。两路独立采集，通过已有绑定和来源配置生成投递任务。不同目标群并发发送，同一目标群一次只发送一条，同来源到同目标保序。某一来源失败不阻塞其他来源，某群不可用不阻塞其他群；账号级限流统一退避。

总体验收需要覆盖两路同时来消息、突发积压、单路读取超时、单群发送失败、账号级限流、停止与恢复，以及现有飞书图片和补发功能回归。真实发送仅在用户指定的测试来源与目标群上进行。

## 阶段边界

| 阶段 | 范围 | 独立验收 | 当前状态 |
| --- | --- | --- | --- |
| 一 | 持久化投递队列、调度器、模拟双来源运行骨架 | 原子入队、来源保序、公平调度、并发上限、重试隔离、停止恢复 | 已实现，11 项单测和双来源演示通过 |
| 二 | 飞书采集进度与投递解耦、文本和图片适配、QQ 通知采集与匹配、真实发送适配 | 两路真实消息按配置投递；已有文本、图片与补发行为兼容 | 待阶段一确认后实施 |
| 三 | 顶部统一启停、单平台启停、两路状态、错误恢复入口、启动文档 | UI 启停与进程生命周期一致，双路同时运行并完成故障验收 | 待前阶段确认后实施 |

阶段一是隔离的可运行骨架，尚未替换正式飞书转发或接入 QQ 通知；现有 `start.command` 和管理页行为不变。每阶段完成验证后再确认下一阶段，不将模拟结果当作生产性能结果。

## 阶段一的队列约定

- `DeliveryStore.enqueue(source, message, targets, payload)` 在一个 SQLite 事务中保存所有目标。调用成功后采集方才可提交自己的进度；事务失败必须保留进度。若保存任务后进度提交前退出，重放相同“来源、消息、目标”会被去重。
- 每次入队的目标列表是路由快照。阶段二需明确配置删除、目标解绑和历史任务的处理，发送前检查目标仍有效。
- 待投递负载存在本地 SQLite 中，文件权限为 `0600`，成功后清空负载，仅保留去重标识。启用 SQLite `secure_delete`，但不承诺清除系统备份或磁盘快照。阶段二必须更新正式运行时数据说明；现有生产路径仍不保存消息正文。
- 默认最多 10,000 条未完成投递、100,000 条总记录，单负载最多 64 KiB；容量满时拒绝整条新消息，不删除未发送内容或去重记录。阶段二需加入按采集高水位安全回收去重记录及容量告警，QQ 通知无法重拉时必须明确报告采集缺口。
- 来源队列由“来源 × 目标群”确定。按入队顺序保序，因此适配器必须按真实来源顺序提交；不承诺跨平台的全局时间排序。
- 各目标群、各来源队列按最近调度轮次公平选择。重试中的队头挡住同来源后续消息，但不占发送名额，也不挡住其他来源。
- 一次只加载实际在途任务，不把所有负载读入内存。默认最多 4 个目标群并发、两次派发至少间隔 0.1 秒；这些是骨架的可配置初值，不是 QQ 接口额度结论。
- 发送适配器每次只能发起一次尝试，应支持超时取消；不能复用内部等待重试的旧发送包装器。调度器负责有限指数退避或按适配器给出的消息级、群级、账号级延迟重试。
- 超出重试预算后保留任务并阻塞其来源队列，等待显式恢复；目标失效单独暂停该群。状态接口和人工恢复入口在后续阶段接入。
- 停止后不再领取新任务，等在途请求收尾；强制取消或异常退出后将未确认任务恢复为待发送。网络超时、服务端成功但本机尚未确认等场景可能重复投递，不宣称恰好一次。
- 文件锁确保同一队列只有一个服务拥有者。采集适配器在统一事件循环中提交任务，不能在其他线程直接访问此连接。

## 验证与运行

在本阶段工作树根目录使用 Python 3.12：

```bash
/opt/homebrew/bin/python3.12 -m unittest Tests.test_delivery_dispatcher -v
/opt/homebrew/bin/python3.12 delivery_demo.py
```

演示只使用临时目录和模拟发送端，不读取凭证、不连接外部账号。两路来源各产生 3 条消息，每条分发到两个群；第一次飞书向群 A 发送失败后延迟重试。实测 12 次成功投递、13 次发送尝试，最大并行群数为 2，四条来源到目标的队列均保持 `1 → 2 → 3` 顺序。

11 项单测覆盖原子分发与容量回滚、重复入队、成功后负载清理、来源公平性、同群互斥、重试期间保序、群级及账号级退避、暂停恢复、进程独占与重启恢复、并发上限、正常停止、取消与超时。

## 阶段二需要完成的适配

1. 将现有飞书“发送后推进游标”拆为采集高水位和逐目标投递确认，兼容已有游标及补发路径，避免升级重放。
2. 图片任务保存可重新下载的飞书资源引用，不保存临时图片路径；明确图文多段任务的部分成功与恢复语义。
3. 使用真实 QQ 通知样本验证群名、发送人、正文和通知标识；验证折叠、同文连续通知、静音和重复通知的边界。无法辨别的重复或缺失不得伪装成精确采集。
4. 发送适配器复用 SDK 客户端及凭证读取，核对真实错误结构后映射重试、目标暂停、审核拒绝和账号退避。手动发送、补发和自动发送的统一出口也在本阶段处理。
5. 增加队列状态、容量告警、去重记录回收及生命周期接口，供阶段三 UI 使用。
