# 飞书与 QQ 统一转发实施计划

## 目标与总体验收

一个控制面管理两路采集及统一投递调度器。顶部支持启动全部、停止全部，并显示飞书与 QQ 各自状态；Tab 保留来源与目标配置，并支持单独启停。

飞书继续通过 API 获取文本、图片及现有富文本内容；QQ 第一版读取系统通知文本。两路独立采集，通过已有绑定和来源配置生成投递任务。不同目标群并发发送，同一目标群一次只发送一条，同来源到同目标保序。某一来源失败不阻塞其他来源，某群不可用不阻塞其他群；账号级限流统一退避。

总体验收需要覆盖两路同时来消息、突发积压、单路读取超时、单群发送失败、账号级限流、停止与恢复，以及现有飞书图片和补发功能回归。真实发送仅在用户指定的测试来源与目标群上进行。

## 阶段一的队列约定

- `DeliveryStore.enqueue(source, message, targets, payload)` 在一个 SQLite 事务中保存所有目标。调用成功后采集方才可提交自己的进度；事务失败必须保留进度。若保存任务后进度提交前退出，重放相同“来源、消息、目标”会被去重。
- 每次入队的目标列表是路由快照。后续配置变更仅影响新事件，发送前检查目标仍有效；失效目标暂停并保留任务。
- 待投递负载存在本地 SQLite 中，文件权限为 `0600`，成功后清空负载，仅保留去重标识。启用 SQLite `secure_delete`，但不承诺清除系统备份或磁盘快照。新版运行时的数据保存和清理范围见 README。
- 默认最多 10,000 条未完成投递、100,000 条总记录，单负载最多 64 KiB；容量满时拒绝整条新消息，不删除未发送内容或去重记录。近期回执保留至少 24 小时，仅回收已导出确认的事件；80% 积压提示，满容量背压。QQ 暂存达到上限停止监听并提示失败，无法重拉停止期间缺失的通知。
- 来源队列由“来源 × 目标群”确定。按入队顺序保序，因此适配器必须按真实来源顺序提交；不承诺跨平台的全局时间排序。
- 各目标群、各来源队列按最近调度轮次公平选择。重试中的队头挡住同来源后续消息，但不占发送名额，也不挡住其他来源。
- 一次只加载实际在途任务，不把所有负载读入内存。默认最多 4 个目标群并发、两次派发至少间隔 0.1 秒；这些是骨架的可配置初值，不是 QQ 接口额度结论。
- 发送适配器每次只能发起一次尝试，应支持超时取消；不能复用内部等待重试的旧发送包装器。调度器负责有限指数退避或按适配器给出的消息级、群级、账号级延迟重试。
- 按用户确认的策略，单条消息最多尝试 5 次；重试耗尽后记录 `retry_exhausted` 并跳过该目标的剩余内容，不继续阻塞后续消息。旧队列中达到上限的受阻任务在启动时按相同策略处理，选择性补发仅处理所选任务。账号退避仍保留，目标失效单独暂停该群。`/api/status` 提供近期跳过计数，日志记录任务编号；图形化恢复入口属于第三阶段。
- 停止后不再领取新任务，等在途请求收尾；强制取消或异常退出后将未确认任务恢复为待发送。网络超时、服务端成功但本机尚未确认等场景可能重复投递，不宣称恰好一次。
- 文件锁确保同一队列只有一个服务拥有者。采集适配器在统一事件循环中提交任务，不能在其他线程直接访问此连接。

## 验证与运行

在本阶段工作树根目录使用 Python 3.12：

```bash
/opt/homebrew/bin/python3.12 -m unittest Tests.test_delivery_dispatcher -v
/opt/homebrew/bin/python3.12 delivery_demo.py
```

演示只使用临时目录和模拟发送端，不读取凭证、不连接外部账号。两路来源各产生 3 条消息，每条分发到两个群；第一次飞书向群 A 发送失败后延迟重试。实测 12 次成功投递、13 次发送尝试，最大并行群数为 2，四条来源到目标的队列均保持 `1 → 2 → 3` 顺序。

11 项单测覆盖原子分发与容量回滚、重复入队、成功后负载清理、来源公平性、同群互斥、重试期间保序、群级及账号级退避、暂停恢复、进程独占与重启恢复、并发上限、正常停止、取消与超时。

## 阶段二实现与待验收

已实现飞书采集高水位与旧确认游标分离、旧按群确认迁移、文本/图片/富文本适配、图片分段恢复、QQ 通知暂存与规则匹配、手动及补发统一出口、容量告警、去重回收和 CLI 恢复入口。补发前预检顺序，拒绝时不新增队列任务；补发只派发本次选中的目标。默认 prime 保留积压，force-end 在持锁状态下同时取消主来源队列并推进位置。

QQ 只以系统可见通知作为输入，群名精确匹配，发送人匹配副标题或正文前缀；这些规则已通过夹具验证，尚缺本机真实 QQ 通知样本。真实测试需验证群名/发送人映射、同文通知、折叠、静音、长文截断，以及指定测试群中收到文本和飞书图片。

自动验证命令使用已安装 `requirements-qq.txt` 的 Python 3.12 环境：

```bash
.venv/bin/python -m unittest Tests.test_unified_delivery Tests.test_delivery_dispatcher Tests.test_control_plane Tests.test_qq_sources -v
swift test
swift build -c release
```

新增双路测试覆盖原子高水位、配置快照、生产者独占边界、连续确认与发布失败隔离、部分成功迁移、图文恢复、精确单次发送、QQ 重复通知与背压保留、手动单出口、补发目标选择及无副作用拒绝、force-end、队列恢复、状态脱敏和完整双路运行/停止。真实链路与吞吐尚未验收，不将这些模拟测试视为第二阶段全部验收完成。
